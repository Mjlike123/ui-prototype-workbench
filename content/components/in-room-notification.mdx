## 使用场景

房间内通知用于**语音房、游戏房等沉浸场景**中，在不打断主界面的前提下提示用户关注某条消息、邀请或系统事件。它悬浮在房间内容之上，通常出现在顶部或中部，而不是系统级 Push 或应用内全屏弹窗。

典型场景：

- 好友进房、@ 提醒、礼物或任务完成提示
- 需要用户快速确认或跳转的轻量操作（如「加入」「查看」）
- 暗色房间背景上使用深色通知条，亮色场景使用浅色通知条

## 结构

自左向右：

1. **头像**（可选）：48pt 圆形，0.5pt 浅描边
2. **文案区**：双行（16pt 标题 + 14pt 描述）或单行 14pt 描述
3. **操作区**（可选）：32pt 品牌主按钮、14pt 品牌文字链 + 20pt 右箭头，或无操作

容器规格：最小高 80pt、圆角 12pt、内边距 16pt、元素间距 12pt，设计稿宽度 343pt。

## 表面语气

| 语气 | 背景 | 标题色 | 适用 |
| --- | --- | --- | --- |
| `light` | 白 90% + 浅描边 + 轻阴影 | primary | 浅色房间、浅色遮罩上 |
| `dark` | 黑 80% + 模糊 + 深阴影 | white | 暗色房间、视频/舞台背景上 |

描述文案在两种语气下均使用 `color.text.secondary`（#8B8C91）。

## 布局与操作

| layout | 文案 | 使用时机 |
| --- | --- | --- |
| `stacked` | 标题 + 描述 | 需要区分主副信息 |
| `compact` | 单行描述 | 信息较短或重复强调 |

| action | 视觉 | 使用时机 |
| --- | --- | --- |
| `button` | 32pt 品牌胶囊按钮 | 主路径确认、加入、接受 |
| `link` | 品牌文字 + 右箭头 | 次要跳转，如「查看详情」 |
| `none` | 无右侧操作 | 纯告知，数秒后自动消失 |

同一页面同时只应出现**一条**房间内通知；新通知应替换旧通知，不要纵向堆叠多条。

## 交互

- 点击主按钮或文字链：执行业务回调（跳转、确认、关闭通知）
- 无操作时：由业务决定自动消失时长（建议 3–5 秒）或滑动关闭
- 点击通知非操作区域：可选进入详情；若无可跳转目标，不应伪装成可点击

## 可访问性

- 使用 `role="region"` 并提供可感知名称（标题或 `aria-label`）
- 操作必须是 `<button>`，不能只依赖颜色表达可点
- 自动消失的通知应保留足够阅读时间，并避免在朗读过程中突然移除

## 与其他组件的关系

| 组件 | 关系 |
| --- | --- |
| `avatar` | 通知条头像复用 48pt 圆形头像规格 |
| `button` | 右侧主操作复用 32pt 品牌主按钮样式 |
| `action-panel` | 半屏动作列表用于多选项；通知条仅承载单条轻量提示 |
| `empty-state` | 空状态用于页面级无内容；通知条用于临时浮层反馈 |

## 避免

- 在房间内同时堆叠多条通知
- 用通知条承载长文或多按钮决策（应使用半屏或全屏页）
- 在浅色通知条上使用浅色描述导致对比不足
- 省略可访问名称，仅依赖头像传达含义
