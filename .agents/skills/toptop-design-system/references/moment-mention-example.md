# 动态 @ 好友：增量功能设计样例

来源：用户对动态发布和评论流程的说明及 Figma 参考节点 `65:14349`。这是本次需求的设计依据，不把截图本身当作组件规范。

| 需求变化 | 原页面基线 | 应新增的状态或区域 | 组件判断 |
| --- | --- | --- | --- |
| 发布动态时 @ 好友 | 保留发布器原有 375pt 网格、文案区、图片位、话题栏、工具栏、键盘与发布按钮 | 工具栏增加 @ 入口；正文输入 `@` 后显示提及文本 | 入口按原工具栏图标尺寸与间距落位；正文中的昵称用品牌色语义表达，保留用户已有文案与图片 |
| 选择好友 | 保留发布器作为蒙层下的上下文 | 打开半屏，搜索、好友列表、未选中、已选中、完成按钮 | 复用 TopTop 半屏内容容器 Kit；搜索和好友行按其内容契约组合。`action-panel` 仅适合动作菜单，不适合可搜索列表 |
| 完成提及 | 返回原发布器及原光标上下文 | 选中好友的昵称插入正文，草稿和媒体保持原样 | 完成按钮只在有选择时可操作；插入结果需要独立画板验证，不停留在选中态 |
| 评论中 @ 好友 | 保留动态详情的作者、正文、媒体、评论层级与底部回复区 | 评论正文内出现可辨识的 @ 昵称 | 按原评论排版与品牌色显示；不要为展示态额外造一个与发布器不同的 UI 模式 |

## 验收问题

1. 去掉新增的 @ 功能后，页面网格与原稿是否仍一致？
2. @ 入口、好友半屏和评论提及是否分别有明确的触发与结果？
3. 半屏的 Kit 外壳是否仍是组件实例？搜索与列表是否符合任务语义？
4. 未选中与已选中是否有可辨识差异；完成操作是否与选择状态一致？
5. 返回发布器后，原文案、图片和插入的昵称是否同时存在？
6. 评论中的昵称是否跟随原评论文本层级，而非覆盖评论或新增无关控件？
