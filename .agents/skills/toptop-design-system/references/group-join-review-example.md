# 群聊入群审核与群通知：增量设计示例

Figma 设计稿：[群聊入群审核流程](https://www.figma.com/design/JbG9tc63Ro1d4OrMTdNcbK/V3.30.0?node-id=179-7461)

## 群类型边界

- 普通多人群：成员区保留添加与移除入口；设置页内嵌「加群需要审核」「仅群主和管理员可邀请」两个开关，只有群主可修改。两开关默认关闭：所有成员可邀请，邀请成功即入群。审核开启后，被邀请人与主动申请者需管理员同意；邀请权限开启后，普通成员不显示添加入口。保留本群待处理、群管理员和群主解散入口。
- 房间群与家族群：设置页成员预览不显示添加或移除入口；不显示上述两个普通群开关和 IM 群管理员入口。「查看更多群成员」进入对应成员列表；家族群的邀请与移除入口放在成员列表。全体禁言按各群当前详情页契约展示。
- 设置页的「待处理进群申请」只进入当前群的申请列表。

## 申请与通知

- 本群申请列表：第一行显示昵称与 `yyyy/MM/dd` 日期，第二行说明申请加入或被谁邀请加入当前群，第三行的「拒绝／通过」按钮右对齐。处理后保留该行，以「已通过／已拒绝」显示结果。
- 消息列表的「群通知」是跨群汇总入口，显示最新一条申请摘要、时间和未读状态。进入后可混排各群申请、邀请及「已退出」记录；退出记录没有处理按钮。
- 不另建一条邀请或申请结果通知推送给邀请人、申请人或被邀请人。房间群主动申请沿用既有房间入口和待审流程。

## 设计复用

从现有设置页、申请页、消息列表复制可编辑基线，复用状态栏、导航、头像、开关、按钮和通知图标。按业务语义增删入口与状态；不要把普通群管理能力机械复制到房间群或家族群。

移动端内容区左右边距各为 16pt。列表内容和设置行填满扣除边距后的容器宽度；使用自动布局时检查行的实际宽度，避免 Hug 内容把整行缩窄。通栏行的背景可铺满屏宽，内部内容仍对齐 16pt。

同类相邻 cell、设置行及操作项之间用 0.5pt 分割线切分信息，元素轮廓描边也用 0.5pt；不同属性的功能模块之间用 4pt 分隔带。普通分割线随内容容器延展、左右各内缩 16pt；大模块分隔带可铺满容器。两者颜色均绑定 TopTop 本地变量「分割线透明/bordBg1」（`color.border.subtle`）。icon Kit 矢量图形自身的笔画宽度沿用组件规范。

家族群设置页的导航、成员概览和设置行背景与页面背景一致，统一绑定 `color.surface.canvas`（背景色/bgPrimary）；不要给这些元素绑定 `color.surface.panel`（黑白色背景/背景色-白）。按钮、头像等有独立语义的素材仍使用各自的 Token 或组件状态。

列表文案在自动布局中设为 Fill，填满头像与右侧操作之间的剩余宽度；文字与右侧元素的间距按关系选择 16pt、12pt 或 8pt，不能靠固定文字框宽度留下偶然空白。右侧控件仍保持距屏幕或内容容器边缘 16pt。
