# TopTop 原型综合验收

默认只读。只有用户明确要求修复时，才进入实现 Skill 或专项改进 Skill。

## 审查输入

至少确认：

- 用户目标和主要任务
- 页面截图、运行地址或实现文件
- 使用的 componentId / Manifest
- 目标视口和平台
- Prototype 功能合同与候选记录（存在 `candidate` 时）

## 最小读取范围

1. Manifest 中列出的组件 YAML。
2. 对应 Foundations 和 Interaction YAML。
3. 相关实现文件与样式。
4. 必要时查看运行截图。

不要默认加载整个 Monkren references。

## 五层审查

### A. 视觉审美

- 先只看目标视口截图，判断它是否明显属于当前产品，而不是可替换品牌名的通用模板
- 第一视线和信息层级是否明确
- 间距、密度和节奏是否稳定
- 颜色、字体和图标是否来自 Kit
- 是否出现模板化 AI slop
- 内容与素材是否真实可信；同图是否被伪装成多个作者、品类或实体
- 选定方向是否只有一个首屏主角、一个明确记忆点，并完成过减法

需要深查时调用：

- `monkren-design/skills/04-review/5-dim-review`
- `ai-slop-check`
- `hierarchy-rhythm-review`

### B. 设计规范

- 每个可见模块能否追溯到 componentId
- Variant、Slot、Token 和内容约束是否匹配
- 未指定区域/包时是否默认使用 `color.brand.primary`（`#16D8C8`）；`color.ku.*`、`color.brand.tw-*` 是否都有明确需求或既有页面契约依据
- 自定义区域是否被诚实标为 Kit gap
- 没有用近似组件掩盖缺失契约

### C. 交互逻辑

- 用户能否完成主要任务
- 导航、Tab、列表行和 CTA 是否有可见结果
- selected、pressed、focus、empty、error 是否合理
- 是否存在静默操作、死路或状态互相矛盾

需要深查时调用 `interaction-states-pass`。

### D. 交付完整性

- Manifest、实现和截图是否指向同一版本
- H5 是否通过 375×812、466×678、890×626 与可访问性检查
- 像素要求是否有 Yueban/截图证据
- iOS 实机要求是否明确为后续 Lookin 验收
- 新页面或整页改版是否保留至少两轮“截图 → 独立审查 → 修正”证据

### E. Kit 候选门禁

仅审查 Manifest / `designSystemMapping` 中显式记录的 candidate。页面设计优秀不等于适合进入 Kit。

依次判断：

1. **真实缺口**：现有 Kit 组件或组合是否确实无法在不扭曲语义的前提下完成任务；
2. **功能合同**：用户任务、触发、输入、结果、信息优先级和探索边界是否明确；
3. **组件边界**：候选是否拥有单一稳定语义，而不是把页面布局或业务内容整体封装；
4. **状态完整性**：Variants、默认与异常状态、关闭、撤销、恢复和无障碍行为是否可定义；
5. **系统适配**：是否使用 Foundations Token，且不要求覆写既有 Kit 内部契约；
6. **复用证据**：是否有两个稳定场景，或有产品 / Kit owner 对平台级基础能力的确认；
7. **运行证据**：是否已在代表性原型、目标视口和主流程中验证；
8. **可维护性**：能否补齐 YAML、MDX、Interaction、实现、测试和参考预览。

候选结论只能是：

- `keep-prototype`：方案有效，但复用或稳定性证据不足；
- `nominate`：满足门禁，可交给 `toptop-design-system` 建立 `draft`；
- `reject`：错误分类、已有替代、边界不成立或维护成本不合理。

`nominate` 不等于 `stable`，也不授权直接改现有组件 API。存在未决产品、内容、能力或工程 blocker 时不得提名。

## 高质量交付门槛

方向探索阶段只评差异与决策价值，不要求候选稿达到交付门槛。选定方向进入完整实现后，只有同时满足以下条件才可判定“可交付”：

- 无 P0、P1；
- 四项简分均不低于 8/10，视觉审美必须有运行截图证据；
- 主 CTA 完成真实、可观察、可恢复的端到端结果，不只显示 Toast；
- 主要控制触控区域不小于 44 × 44pt，筛选、收藏和选择均有持久选中态；
- 首屏内容、图片与数据不通过重复素材伪装多样性；
- 目标视口、关键状态、独立评审和修正证据齐全。

不能因为组件和 Token 合规而提高视觉评分；也不能因为截图好看而忽略状态、无障碍和任务完成。

## 严重度

- **P0**：主要任务不可完成、核心模块错误、严重误导或无障碍阻断。
- **P1**：明显违反 Kit、关键状态缺失、交付后高概率返工。
- **P2**：局部层级、文案、节奏和细节优化。

## 输出格式

```text
结论：可交付 / 有条件可交付 / 不可交付

P0
- [位置] 问题 — 影响 — 证据（spec 或 file:line）— 修复方向

P1
...

P2
...

简分
- 视觉审美 x/10：证据
- 设计一致性 x/10：证据
- 交互逻辑 x/10：证据
- 交付完整性 x/10：证据

未决 Kit gaps
- ...

Kit candidates
- [candidateId] keep-prototype / nominate / reject — 复用证据 — 验证证据 — blocker
```

没有证据的意见不列为问题。不要因为“看起来不错”跳过功能和状态验证。
