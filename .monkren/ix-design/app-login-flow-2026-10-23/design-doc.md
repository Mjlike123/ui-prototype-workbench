# TopTop App 登录流程

**日期**：2026-10-23  
**平台**：iOS / Studio 原型  
**项目**：`app-login-flow`  
**入口**：`/canvas/studio/app-login-flow`

## 目标

让用户在一个首屏内识别 TopTop、找到上次使用的登录方式，并能通过 Apple、Google、手机号或 TopTop ID 完成登录。手机号路径覆盖输入、校验、验证码、错误恢复与成功终点。

## 输入与取舍

用户提供两组参考：

- 登录首页：采用“大品牌主视觉 + 最近登录方式 + 其他方式 + 协议”的层级。
- 手机号输入：采用“单字段、国家区号、输入后启用主按钮”的结构。

没有复制参考图中的品牌素材；Facebook 与 Snapchat 已按用户确认移除。Mobbin 外部流程检索因付费权限不可用，本次依据用户参考图、TopTop Kit 与内部交互规范完成。

## 质量方向卡

- **品类与主任务**：社交 App 身份认证；选择方式并进入 App。
- **首屏主角**：原创 Toppy 穿过青色社交入口的 3D 主视觉。
- **产品特异性**：Toppy、TopTop 青、上次使用识别和“进入社交世界”的叙事。
- **视觉语言**：大留白、青色光晕、黑白主按钮、少量暖黄色提示。
- **记忆点**：认证成功后 Toppy 完成进入动作，明确结束登录任务。
- **内容真实性**：使用真实方法名称和可执行文案；第三方授权仅模拟，不伪装真实 SDK。
- **验收**：375 / 466 / 890 三种视口、44pt 触控区、完整成功与错误恢复、两轮截图审查。

## 页面与主流程

```text
登录首页
  ├─ Apple / Google → 授权中 → 成功 / 失败重试
  ├─ 手机号 → 号码校验 → 发送验证码
  │            → 六位验证码 → 错误 / 过期 / 重发 → 成功
  └─ TopTop ID → ID 输入 → 成功 / 错误

成功 → 进入 TopTop
```

### 1. 登录首页

- 上半屏建立品牌与情绪，下半屏完成决策。
- Apple 作为上次使用方式独占主按钮。
- Google 为次级完整按钮；手机号和 TopTop ID 使用同层级的紧凑入口。
- 协议始终可见，服务条款与隐私政策为独立链接。

### 2. 手机号输入

- 国家区号与手机号放在同一 48pt 字段。
- 输入为空时“获取验证码”禁用；格式有效后启用。
- 清除按钮不少于 44pt，错误文案与输入框关联。
- 发送期间按钮显示进度并禁止重复提交。

### 3. 验证码

- 单一原生数字输入承载六个视觉槽，支持粘贴和退格。
- 输入六位后自动验证；原型成功码为 `123456`。
- 其他六位数字展示错误并保留恢复路径。
- 30 秒后允许重新发送；原型提供“快速结束倒计时”以便评审状态。

### 4. 登录成功

- 不以 Toast 结束主任务。
- 展示明确成功页、登录方式和“进入 TopTop”主按钮。

## Kit 与缺口

### 复用 Kit

- `IosStatusBar`
- `SystemIcon`
- `kitButton` 契约类名
- Foundation 颜色、间距、圆角、字体与动效 Token

### Prototype gaps

- `PrototypeLoginHero`：原创登录品牌主视觉。
- `PrototypeAuthProviderMark`：第三方方式文字标记；不冒充系统图标。
- `PrototypeAuthField`：国家区号 + 手机号 / TopTop ID 表单字段。
- `PrototypeOtpInput`：单输入控件驱动六槽视觉。
- `PrototypeAuthSuccess`：完成认证后的可观察终点。

## 响应式策略

- **375×812**：单列，主视觉约占首屏上半区，全部主要登录方式和协议保持可见。
- **466×678**：压缩主视觉高度，减少垂直空白，保证小高度设备完整显示。
- **890×626**：左侧品牌主视觉，右侧认证表单；不把手机单列机械放大。

## 状态与无障碍

- 所有可见控制至少 44×44pt。
- 页面切换后标题获得程序化焦点；返回后恢复来源。
- 输入错误通过 `aria-invalid` 与 `aria-describedby` 关联。
- loading 使用可见文案与 `aria-live`。
- `prefers-reduced-motion` 下关闭漂浮和页面位移动画。
- 状态栏仅作原型系统界面，隐藏于辅助技术。

## 待生产确认
