# Moment 发布入口与动态详情优化 · UX 设计说明

**版本：** v0.1  
**日期：** 2026-09-07  
**状态：** 交互设计稿，待产品评审  
**目标版本：** v3.19.0，全大区

## 1. 设计目标

### 1.1 背景

发布引导已验证能提升各大区的内容发布。当前需求进一步把发布入口移至移动端更易触达的右下区域，并把动态详情中的身份与互动操作固定在视口边缘，以提升发布和互动渗透。

### 1.2 用户与核心任务

- Moment 浏览者：不离开浏览上下文即可发起发布。
- My Moment 用户：查看历史内容时可继续创作，且不强制选择圈子。
- 纯文案发布者：客户端不被旧配图规则提前阻断。
- 动态详情浏览者：长内容滚动过程中始终可识别作者并完成互动。
- 发布失败用户：不重复输入即可恢复失败草稿。

### 1.3 设计原则

1. **只设计增量**：线上已有发布、点赞、评论、Chat 与添加行为直接复用。
2. **主操作唯一**：Moment 右下角只保留发布 FAB，不与礼包入口竞争。
3. **保护用户投入**：服务端拒绝和网络失败均不清空草稿。
4. **配置归服务端、反馈归客户端**：客户端不复制圈子配图规则，但必须承接提交中、拒绝原因与恢复。
5. **固定控件不遮挡内容**：列表、详情正文、键盘与安全区均预留正确 inset。

## 3. 总体流程

### 3.1 Moment 发布

```text
Friend / Find / Room members
  → 点击右下发布 FAB
  → 进入现有发布器（携带来源；Find 可预选当前圈子）
  → 编辑并提交
  → 服务端校验圈子规则
  → 成功返回来源 Feed / 失败保留草稿
```

### 3.2 My Moment 发布

```text
My Moment → 点击发布 FAB → 发布器（不预选圈子）→ 发布
```

### 3.3 发布失败恢复

```text
Feed 中 Post failed
  → 点击失败项
  → 恢复文案、媒体、圈子、可见范围
  → 聚焦需修正字段
  → 再次提交
```

### 3.4 动态详情互动

```text
进入详情
  → 作者栏固定顶部
  → 正文与评论滚动
  → 底部随时点赞 / 评论 / Chat
  → 本人或 ME/KSA：隐藏 Chat，输入框扩展
```

## 4. 页面与状态

### 4.1 Moment 列表（`moment-feed`）

**结构**

- 顶部：`PrimaryNavigation`，Friend / Find / Room members。
- 中部：沿用 Feed 卡片。
- 右下：复用 Core `prototypeFeedCompose` 发布 FAB，位于底部导航上方。
- 失败态：列表上方出现可点击 `Post failed` 条目。
- 底部：`BottomNavigation`。

**交互**

- FAB 在三个 Feed 表面持续存在，不随内容滚动。
- 最后一条 Feed 可完整滚动到 FAB 上方。
- 点击失败项进入同一发布器，不创建第二套“重试页面”。
- 原礼包悬浮入口不与 FAB 共存。

### 4.2 My Moment（`my-moment`）

**结构**

- `RegularNavigation` + 自己的动态列表 + 右下发布 FAB。
- 空列表仍保留发布入口，并提供首发引导。

**交互**

- 点击 FAB 进入发布器，`community=null`。
- 点击自己的动态进入详情，并自动应用“本人动态”状态。

### 4.3 发布器（`feed-compose`）

**复用**

- Studio 原型直接渲染 Core `FeedComposePagePrototype`，完整复用其布局、文案编辑、Kit button、`PrototypeFeedMediaPicker`、话题、可见范围半窗与草稿保存；不维护第二套发布页 CSS。

**新增**

- 圈子选择属于 page-level gap，只在 Core 发布页之上增加最小扩展，不改写主体布局；`Select Community` 使用 `RegularListItem`。
- 新圈子存在时入口显示红点；打开面板后入口红点消失。
- 新圈子行继续显示红点，关闭面板后消费。
- 客户端 Post 可用性只判断“是否有内容”和“是否正在提交”，不判断圈子是否必须配图。
- 服务端拒绝后显示原因、保留草稿并允许添加图片后重试。

**关键状态**

- 空草稿、可发布、提交中、服务端拒绝、网络失败、失败草稿恢复。
- 圈子面板 loading / error / 未选择 / 已选择 / 新圈子。

### 4.4 动态详情（`feed-detail`）

**结构**

- 吸顶作者栏：返回、头像、名称、标签、条件性添加、更多。
- 中间滚动区：正文、媒体、时间、评论/点赞 Tab、评论列表。
- 吸底互动栏：评论输入、点赞、评论、条件性 Chat。

**状态规则**

- 未添加的他人动态：添加 + 更多 + Chat。
- 已添加用户：隐藏添加。
- 自己的动态：隐藏添加和 Chat。
- ME、KSA：隐藏 Chat。
- Chat 隐藏后，评论输入框自适应扩展。
- 键盘出现时输入栏贴合键盘顶部；键盘关闭时回到底部安全区。
- 点赞失败时回滚选中态与数值，并给出轻反馈。

## 5. 竞品与模式依据

- Material 3：FAB 代表页面主操作，适合固定在底部导航上方。
- Instagram：草稿应支持返回创建流程继续编辑，并明确保存边界。
- Apple：底部输入控件应跟随键盘与安全区。
- NN/g：固定 header 可提高可发现性，但需紧凑、避免遮挡与无意义动画。

完整依据见 `research.md`。

## 6. 相对 PRD 的 UX 补全

### 已直接补入交互稿

- FAB 与底部导航、安全区及最后一条内容的避让。
- 键盘出现和收起时的底部互动栏行为。
- 服务端拒绝、网络失败与点赞失败的反馈和回滚。
- 新圈子入口/选项两级红点的消费时机。
- 防止重复提交，失败不清空草稿。

### 体验建议

- 失败草稿恢复后聚焦首个需修正字段。
- My Moment 空态直接引导发布。
- 固定作者栏和互动栏仅做按压与状态切换动画，不做滚动缩放。

### 待产品确认

1. 礼包入口是彻底下线还是迁移？
2. “当前发布草稿”是否必须完整恢复文案、媒体、圈子、可见范围与来源？
3. 纯文案被拒绝时的正式错误码和文案是什么？
4. 新圈子红点是否跨设备同步，消费状态由前端还是后端持久化？
5. 旧版客户端如何处理新圈子和纯文案圈子配置？
6. 是否补充 FAB 曝光/点击/来源、失败恢复及详情互动埋点？
7. 图片加载失败、内容删除、无权限是否属于本期详情异常态？

## 7. Kit 映射

- 一级导航：`primary-navigation`
- 二级页导航：`regular-navigation`
- 底部导航：`bottom-navigation`
- 圈子选择：`regular-list`
- 发布 CTA：`button`
- 作者信息：`avatar` + `list-tag`
- 评论输入：`chat-input`
- 所有语义图标：`SystemIcon`
- Feed、Feed Detail、媒体选择：复用现有 Prototype 模块

**Kit gaps**

- 发布 FAB：复用 Core `prototypeFeedCompose`，当前 Kit 无通用 FAB 契约；本期不新建组件、不提名 stable。
- 吸顶作者 + 吸底互动：属于页面组合规则，不新增组件。
- Feed 卡片仍是 Prototype 模块。

## 8. 动效

- FAB 按压：轻微 scale，80–120ms。
- 失败提示出现：透明度 + 6px 位移，使用 standard duration。
- 圈子半窗：沿用现有 sheet 动画。
- 点赞与添加：只做状态切换，不做夸张弹跳。
- 全部动效响应 `prefers-reduced-motion`。

## 9. 验收清单

- [ ] Friend、Find、Room members 均可通过 FAB 进入发布器。
- [ ] My Moment 进入发布器时不预选圈子。
- [ ] FAB 不遮挡最后一条内容、底部导航或系统安全区。
- [ ] 客户端不会因未配图提前禁用 Post。
- [ ] 服务端拒绝后文案、媒体、圈子和可见范围不丢失。
- [ ] 失败项可恢复草稿。
- [ ] 入口红点和圈子行红点按两级规则消费。
- [ ] 作者栏和互动栏固定，中间内容可完整滚动。
- [ ] 本人及 ME/KSA 不展示 Chat，输入框正确扩展。
- [ ] 评论输入跟随键盘。
- [ ] 所有按钮有可见反馈、键盘焦点与可访问名称。
