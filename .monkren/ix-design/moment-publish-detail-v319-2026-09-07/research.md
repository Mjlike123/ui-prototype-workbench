# Moment 发布与动态详情优化 · 设计研究

**日期：** 2026-09-07  
**研究问题：** 如何提高移动 Feed 的发布与互动可达性，同时避免悬浮入口、吸顶作者栏、吸底互动栏遮挡内容或破坏既有行为？

## 摘要与建议

1. **采用单一发布 FAB**：每个 Moment 表面只保留一个右下角主操作，位于底部导航上方；取消同位置礼包入口，避免两个浮层争夺主操作。
2. **采用紧凑的固定作者栏与底部互动栏**：作者身份与主要动作持续可见，但必须为滚动内容预留上下 padding。
3. **评论输入栏跟随键盘**：激活评论后，输入栏应贴合键盘顶部；回复发送后维持用户上下文。
4. **发布失败必须可恢复**：错误入口不仅“重试”，还应把用户带回完整草稿；必须明确草稿的保存范围和设备边界。
5. **新圈子红点采用分层消费**：入口红点表示“有新圈子”，打开面板后消费；圈子行红点让用户定位具体新增项，面板关闭后再消费。

## 当前状态

- Core 已有 `FeedComposePagePrototype`：文案、图片、可见范围、草稿保存、发布中与错误提示。
- Core 已有 `FeedDetailPagePrototype`：作者栏、评论/点赞 Tab、底部回复输入、点赞/评论/Chat。
- Core Feed 暂无符合本 PRD 的发布 FAB、My Moment 入口和新圈子红点。
- PRD 中大量行为注明“与线上一致”，应作为存量复用，不重新设计。

## 竞品与平台模式

### 1. Material Design 3：FAB 代表页面主操作

Material 将 FAB 定义为页面最主要或最常用操作，并支持置于底部导航上方的 End 位置。对本需求的启示是：发布可以作为 Moment 页唯一悬浮主操作，但不应再与礼包等第二个浮层入口并存。

- 采用：右下角单一发布 FAB；与底部导航、安全区保持固定间距。
- 避免：同一区域叠放多个浮动入口；FAB 随内容卡片滚动。
- 来源：[Material 3 FAB](https://m3.material.io/components/floating-action-button/overview)、[Android FabPosition](https://developer.android.com/reference/kotlin/androidx/compose/material3/FabPosition)

### 2. Instagram：草稿是可恢复的连续任务

Instagram 的发布草稿允许用户回到创建流程继续分享；其官方说明同时明确草稿保存在设备本地，跨设备与卸载后不可恢复。对本需求的启示是：失败内容恢复必须明确数据边界，且进入发布器后应恢复完整编辑上下文，而不只是文案。

- 采用：失败项点击后恢复文案、媒体、圈子、可见范围；提示保存范围。
- 避免：错误项点击后创建空发布器；恢复部分字段却不解释。
- 来源：[Instagram：管理和分享草稿](https://www.facebook.com/help/instagram/1066736386712867/?locale=en_GB)

### 3. Apple：底部输入控件应响应键盘

Apple 的 `UIKeyboardLayoutGuide` 用于让输入栏随键盘出现、移动和收起，并在键盘关闭时遵循底部安全区。对本需求的启示是：动态详情的固定评论栏不能只做 CSS 吸底，必须定义键盘激活状态和安全区行为。

- 采用：输入栏贴合键盘顶部；键盘关闭时贴合安全区。
- 避免：键盘遮挡输入栏；输入态仍保留占空间的点赞/评论/Chat 全套动作。
- 来源：[Apple WWDC23：Keep up with the keyboard](https://developer.apple.com/videos/play/wwdc2023/10281/)

### 4. NN/g：固定栏提高可发现性，但应紧凑且克制动画

NN/g 指出固定 header 能提高其中操作的可发现性，但会占用屏幕空间；应保持尽量紧凑、避免无意义动画、保证不遮挡内容。对动态详情而言，固定作者栏与互动栏成立，但上下栏总高度必须受控。

- 采用：作者栏 44–52pt、互动栏 60pt 左右；正文预留等量滚动空间。
- 避免：大标题与复杂动效；滚动时频繁缩放或跳动。
- 来源：[NN/g：Sticky Headers](https://www.nngroup.com/articles/sticky-headers/)

## 稳定模式

### 模式 A：单一悬浮主操作

- 用途：长列表中的高频创建任务。
- 优点：始终可达，降低从右上角进入的拇指移动成本。
- 风险：遮挡最后一条内容或与底部导航冲突。
- 应用：FAB 固定于导航上方，列表增加 bottom inset；滚动不改变位置。

### 模式 B：固定身份 + 固定互动

- 用途：用户边阅读长内容边互动。
- 优点：保留作者上下文，互动无需回到页面顶部或底部。
- 风险：压缩内容视口。
- 应用：只保留必要身份和动作；本人及 ME/KSA 隐藏 Chat 后输入框扩展。

### 模式 C：失败任务原位恢复

- 用途：服务端校验失败、网络失败。
- 优点：降低重新输入成本，保护用户投入。
- 风险：草稿字段或媒体资源过期导致“看似恢复、实际丢失”。
- 应用：定义完整草稿快照；字段恢复失败时逐项提示。

### 模式 D：两级新内容提示

- 用途：入口需要提示“有新增”，面板还需指出“新增的是哪个”。
- 优点：兼顾发现与定位。
- 风险：消费时机不清导致红点反复出现。
- 应用：入口在打开面板时消费；选项在关闭面板后消费，并记录本地/服务端策略。

## 对当前产品的决策

### Adopt

- Moment 与 My Moment 使用同一 `PrototypeMomentPublishFab`，入口上下文决定是否预选圈子。
- Feed Detail 复用现有作者、标签、评论输入和动作组件，仅新增固定布局及显示规则。
- 发布失败恢复完整草稿，并在错误态保留服务端原因。
- 红点采用入口和选项两级消费模型。

### Avoid

- 不新增第二套发布器。
- 不把礼包入口与发布 FAB 同时放在右下角。
- 不因视觉稿重新定义点赞、评论、Chat 的存量交互。
- 不用纯客户端“是否有图片”规则覆盖后端圈子配置。

### Needs validation

- 右下 FAB 是否遮挡 Feed 卡片操作区及系统安全区。
- 键盘展开时底部动作的收缩方式。
- 草稿恢复范围与媒体资源有效期。
- 红点跨设备同步及消费状态归属。

## 证据限制

- PRD 的数据埋点、数据需求、数据结论和旧版本兼容章节为空。
- 加好友按钮只描述“UI 调整”，具体视觉以 Figma 为准，行为按现网复用。
- 外部研究用于模式验证；最终布局以 TopTop Kit、PRD 与 Figma 为准。
