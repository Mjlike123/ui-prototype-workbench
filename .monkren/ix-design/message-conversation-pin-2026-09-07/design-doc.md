# Message 会话置顶 · UX 设计说明

**版本：** v0.1  
**日期：** 2026-09-07  
**交互设计师：** Agent（toptop-ix-designer）  
**状态：** Studio 原型完成，待交付评审  

## 1. 设计目标

### 背景与真实需求

用户提出的是“会话左滑出现置顶按钮”，真实任务是让重要或高频会话不会被新消息持续下沉，并能在大量会话中稳定、快速地被找到。

因此本期不能只增加一个按钮，还必须补齐：

- 置顶后的列表分区和排序。
- 已置顶状态的视觉识别。
- 取消置顶闭环。
- 侧滑手势与垂直滚动的冲突处理。
- 非手势补充入口。
- 账号同步和失败回滚。

### 目标用户

- 会话较多，需要持续关注少量重要联系人或群聊的用户。
- 高频使用 Message、经常重复搜索同一会话的用户。

### 本期原则

1. 高频整理动作留在 Message 列表原位完成。
2. 置顶是可逆低风险动作，立即生效，不二次确认。
3. 状态既改变位置，也提供轻量视觉和非颜色线索。
4. 沿用 Core Message 的导航、搜索、会话内容和底部导航，只设计增量。
5. 微信只作为交互模式参考，不复制未经版本核实的手势与视觉值。

### 成功标准

- 用户可通过左滑在一次显式点击后完成置顶。
- 用户可通过相同路径或长按菜单取消置顶。
- 新置顶会话固定进入置顶分区第一位。
- 用户能区分“已置顶”与“恰好最近”的会话。
- 侧滑不会明显干扰列表纵向滚动。
- 未读数、消息摘要、时间和进入会话行为不受影响。

## 2. 已确认范围

- 支持类型：私聊、普通群聊、Room Group。
- 不支持类型：系统通知。
- 排序：新置顶会话固定进入置顶区首位；置顶区按置顶时间倒序。
- 数量：不设上限，本期不折叠。
- 同步：账号级跨设备同步。
- 入口：左滑为主入口，长按菜单为补充入口。
- 视觉：置顶行使用弱背景，并增加置顶图标或等价非颜色线索。

## 3. 主流程

```text
进入 Message
  → 找到目标会话
  → 向左滑动
  → 点击“置顶”
  → 会话移动到置顶分区第一位
  → 显示置顶背景与状态线索
```

取消置顶：

```text
左滑已置顶会话
  → 点击“取消置顶”
  → 会话移出置顶分区
  → 按普通时间排序回位
  → 恢复默认视觉
```

补充入口：

```text
长按会话
  → 打开会话操作菜单
  → 置顶 / 取消置顶
  → 执行与侧滑入口相同的状态变化
```

## 4. 页面与交互细节

### Message 消息列表（`message-list`）

页面主体复用现有 Core `PrototypeDestinationPage` 的 Message 信息结构：

1. Message 顶部导航。
2. 搜索。
3. 在线好友。
4. 会话列表。
5. Bottom Navigation。

本期改变会话列表区域，并在不修改 `primary-navigation` Kit 内部结构的前提下，为现有加号增加 Studio 层点击快捷菜单。

### 导航加号点击菜单

- 点击加号后，页面立即出现黑色透明蒙层，气泡菜单锚定在加号下方。
- 菜单包含“创建群聊”和“添加朋友”两个按钮；“添加朋友”复用 `SystemIcon name="follow"`，对应 `icon=关注.svg`。
- 打开时蒙层淡入，气泡从右上锚点缩放淡入；关闭时执行反向动画。
- 点击蒙层、按 Escape 或选择菜单项均可关闭；关闭后焦点返回加号。
- 键盘用户可通过 Tab、Shift+Tab、上下方向键在两个按钮之间循环。
- `prefers-reduced-motion` 下取消进出动画，直接切换最终状态。

### 侧滑

- 手指横向意图明确后，会话行才开始向左跟手。
- 纵向位移占主导时，不进入侧滑，保持列表滚动。
- 未达到展开阈值时释放，会话行回弹。
- 达到阈值时释放，停留并露出一个完整操作按钮。
- 一次最多展开一个会话行；展开新行、点击外部或开始滚动时，旧行自动收起。
- 操作按钮和会话主体是两个独立点击目标，不能同时触发。
- 系统通知不响应置顶手势，也不显示相关菜单项。

### 置顶与取消置顶

- 未置顶会话显示“置顶”。
- 已置顶会话显示“取消置顶”。
- 点击后操作区立即收起并乐观重排。
- 不显示确认弹窗。
- 服务端失败时回滚原位置和状态，提示“操作失败，请重试”。

### 排序

- 列表分为置顶会话和普通会话两个逻辑分区。
- 置顶分区不需要额外大标题，避免增加页面噪音；通过连续弱背景形成视觉组。
- 新置顶会话插入置顶分区第一位。
- 置顶会话收到新消息时不改变置顶分区内部顺序。
- 普通会话继续按最新消息时间排序。
- 取消置顶后，按普通会话最新消息时间回位。

### 视觉区分

推荐方案：

- 置顶会话使用比普通 canvas 略深的低强调度 `surface` 背景。
- 在时间附近增加小型置顶状态图标，或在不挤压时间和未读数的区域提供等价线索。
- 摘要、时间、未读数和头像保持现有样式，避免把置顶误读成告警。
- 侧滑“置顶”使用非危险操作色；“取消置顶”保持同一语义，不使用删除红。
- 可访问名称合并为“{用户名}，已置顶，{摘要}，{时间}，{未读状态}”。

当前 `regular-list` 没有 `pinned` 状态，因此视觉只在 Studio `PrototypePinnedConversationState` 中验证，不修改正式 Kit 契约。

### 动效

- 侧滑跟手，不增加额外装饰动画。
- 操作后以短位移完成列表重排，避免会话瞬移造成定位丢失。
- 状态背景与图标随位置变化同步出现或消失。
- `prefers-reduced-motion` 下直接更新最终位置，不播放重排动画。

## 5. 微信参考与取舍

采用：

- 重要会话固定在列表顶部。
- 置顶后提供弱背景视觉区别。
- 低风险可逆动作直接生效。
- 置顶规模过大可能遮挡普通未读会话，需要产品意识。

不直接照搬：

- 公开资料对微信不同版本的左滑、右滑、长按和设置页入口描述不一致。
- 本方案以用户明确指定的左滑作为 TopTop 主入口。
- 不复制微信的具体色值、按钮宽度或动画。
- 用户已确认不设上限，因此本期不引入微信式折叠置顶。

详细参考：`.monkren/references/message-conversation-pin-2026-09-07/report.md`

## 6. Kit 映射

- 顶部导航：`primary-navigation` / 现有 Message Core 导航。
- 搜索：`search-control`。
- 会话主体：`regular-list` 的 message variant。
- 头像：`avatar`。
- 图标：`SystemIcon`。
- 底部导航：`bottom-navigation`。
- 置顶状态：`PrototypePinnedConversationState`，Kit gap。
- 侧滑操作容器：`PrototypeConversationSwipeAction`，Kit gap。
- 长按菜单：`PrototypeConversationContextMenu`，Kit gap。
- 导航加号：继续复用 `primary-navigation` action 与 `SystemIcon`。
- 加号点击气泡菜单：`PrototypeNavigationQuickMenu`，Kit gap；当前 Kit 尚无锚定导航操作的气泡菜单契约。

复用证据：

- `apps/design-system-portal/src/components/prototypes/prototype-destination-page.tsx`
- `apps/design-system-portal/src/components/kit/regular-list-item.tsx`
- `specs/components/regular-list.yaml`
- `specs/interactions/regular-list-action.yaml`

是否进入 Kit 的后续判断：

1. 至少再有一个稳定列表场景需要通用侧滑动作。
2. 明确多动作、危险动作、RTL、键盘和无障碍行为。
3. 补齐 YAML、MDX、Token、测试和参考预览。
4. 在此之前保持 Prototype，不标为 stable。
