# 语音房在房状态外显 · 竞品与模式研究

**日期：** 2026-09-04  
**研究问题：** 社交/语音产品中，「在房状态」如何外显、谁可见、如何进房、如何与隐私分层？  
**决策用途：** 指导 v3.26.0 个人主页、动态、隐私设置交互验收  
**证据范围：** 飞书 PRD、[Discord Voice API](https://docs.discord.com/developers/resources/voice)、公开 Clubhouse 产品描述；未做实机横评

## 摘要与建议

| 模式 | 代表 | 友好点 | 风险 |
|------|------|--------|------|
| **状态外显 + 一点进房** | PRD 目标形态、Clubhouse 房间列表 | 发现成本低，转化路径短 | 陌生人可见需隐私开关 |
| **频道/房间 API 状态** | Discord voice state | 状态与房间强绑定，可编程 | 偏社区/Guild 语境 |
| **分级隐私 + 隐身覆盖** | 抖音式 Privacy Settings（PRD 参考） | 用户可控可见范围 | 规则层叠需说明清楚 |

**对 v3.26.0 建议：**

1. **采纳** — 在房状态占「在线状态」单槽位，避免双 badge 竞争（PRD 已定义）。
2. **采纳** — 点击状态条直达语音房；埋点区分「个人主页 / 动态」来源（PRD 已定义）。
3. **采纳** — 「所有人 / 仅好友」+ 大区默认策略 + 隐身最高优先级（PRD 已定义）。
4. **补全** — 进房失败、房间结束时的反馈（PRD 未写）。
5. **待确认** — Feed 头像点击与在房条点击的分工（见 openQuestions）。

## 相邻案例

### Discord

- 提供 `voice state` 与频道绑定，客户端可展示「用户在语音频道」([Voice Resource](https://docs.discord.com/developers/resources/voice))。
- **启示：** 在房状态应与「可加入的房间实例」一一对应，点击前应校验房间仍有效。

### Clubhouse

- 首页展示活跃房间，房间内可见参与者；房间为发现与社交核心单元 ([The Conversation](https://theconversation.com/meet-clubhouse-the-voice-only-social-media-app-setting-the-internet-abuzz-154066))。
- **启示：** 「在房」作为社交发现信号合理；但需配套可见范围，避免用户失控感。

### 隐私设置范式（PRD 参考抖音）

- 独立设置项 + 半窗二选一（所有人 / 仅好友）符合用户心智。
- **启示：** 与「隐身于房间」「在线隐身」并列时，必须在 UI 上标明优先级。

## 对当前 PRD 的应用

- **采用：** 三触点（主页客态、动态、隐私设置）与 PRD 一致。
- **避免：** 在无提示情况下向非好友展示房间细节（仅状态条 + 进房，不暴露房间成员列表）。
- **验证：** Figma V3.26.0 与「复用线上头像环样式」是否一致。
